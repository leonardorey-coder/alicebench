# Contributing

Please open an issue for substantial changes. Run `bun run check` and `bun run demo` before proposing a pull request. Keep scenarios fictional and avoid personal data, real credentials, stereotypes and assertions about real people. Include a benign control where appropriate and explain what a criterion tests and how it may fail. Add fixture examples and focused tests for scoring changes; update the suite version and documentation when behavior changes. Never commit API keys or private model responses. The public suite is not a secure hidden evaluation set.
